## 三、需要做什么 — 文件夹组织问题

### 1. `views/SystemManagement/` 23 个文件

```
AssetManagement.vue  ConfigurationCenter.vue  DeviceDetail.vue
DeviceList.vue       LeaveApproval.vue       Maintenance.vue
OperationLog.vue     RepairManagement.vue    RoleManagement.vue
...
```

**问题**：23 个文件挤在一个目录，找页面成本高；菜单项和文件名 1:1，但内部仍然使用 tabs。

**建议重组**：

```
views/SystemManagement/
├── index.vue                 # 总容器，按 meta.module 路由分发
├── assets/                   # 资产管理（4 个文件）
├── devices/                  # 设备相关（5 个）
├── orders/                   # 工单 / 维修 / 配件（5 个）
├── users/                    # 用户 / 角色 / 权限（4 个）
├── logs/                     # 日志（2 个）
└── settings/                 # 配置中心 / 终端（3 个）
```

**分组原则**：按"业务域"分目录，而不是"页面类型"。

### 2. `utils/` 21 个文件 + 1 个空目录

**问题**：
- `api/` 子目录已建但**完全是空的** —— 残留结构
- 21 个 .js 散在同一目录，按字母序找文件很慢
- 同样职责的文件分散在不同位置

**文件清单**（按大小）：

**建议重组为职责子目录**：

```

│   ├── request.js            ← axios 封装

│   ├── realLoader.js         ← 把 realDataLoader 改名
│   ├── excelReader.js
│   ├── dataLoader.js         # 删空骨架
│   └── seededRandom.js
├── format/                   # 通用工具
│   ├── format.js date.js validate.js mask.js pinyin.js clientInfo.js index.js
├── business/                 # 业务工具
│   ├── statistics.js performance.js videoFrame.js interestClassFilter.js echarts.js
```

**预期收益**：21 → 4 个子目录，每个 5-7 文件，找文件路径从 200ms 降到 20ms。

### 验收脚本（写入 `scripts/check-code-structure.mjs`）

```js
// 此脚本只输出报告，不修改任何文件
import fs from 'fs'
import path from 'path'

function walk(dir, out = []) {
  for (const f of fs.readdirSync(dir, { withFileTypes: true })) {
    if (['node_modules', 'dist', '.git'].includes(f.name)) continue
    const p = path.join(dir, f.name)
    if (f.isDirectory()) walk(p, out)
    else if (/\.(vue|js)$/.test(f.name)) {
      out.push({ path: p, lines: fs.readFileSync(p, 'utf8').split('\n').length })
    }
  }
  return out
}

const all = walk('src')
const huge = all.filter(x => x.lines > 1500).sort((a, b) => b.lines - a.lines)
const dirCounts = {}
for (const x of all) {
  const d = path.dirname(x.path)
  dirCounts[d] = (dirCounts[d] || 0) + 1
}
const bloatedDirs = Object.entries(dirCounts)
  .filter(([_, c]) => c > 10)
  .sort((a, b) => b[1] - a[1])

console.log('--- Files > 1500 lines ---')
for (const x of huge) console.log(`  ${String(x.lines).padStart(5)} ${x.path}`)
console.log('\n--- Dirs with > 10 files ---')
for (const [d, c] of bloatedDirs) console.log(`  ${String(c).padStart(3)} ${d}`)

if (huge.length > 0 || bloatedDirs.length > 0) {
  console.log('\nFAIL ❌')
  process.exit(1)
} else {
  console.log('\nPASS ✅')
}
```

跑法：

```bash
node scripts/check-code-structure.mjs
```

## 六、不要做什么（避免过度优化）

1. ❌ **不要为每个 dialog、每个 ref 都拆 hook** —— 只拆真正被复用的逻辑
2. ❌ **不要把 200 行的简单表格页拆成 5 个文件** —— 拆得过细反而难维护
3. ❌ **不要复制整个 utils/ 内容** —— 只是搬位置+改 import 路径
4. ❌ **不要因为"看起来大"就拆纯样式部分**（`:deep` 里的 CSS 该在一起就在一起）
5. ❌ **不要把所有 sub-panel 都做成自动导入** —— 用普通 import 即可
