# 大沩智慧体育运动数据推送对接 - 前端实现计划

## 一、文档概述

本文档基于《大沩智慧体育运动数据推送对接文档 1.1》，规划前端及服务端实现方案。与人员注册对接（我方调用大沩API）不同，**本次对接是我方提供接收接口，大沩设备主动推送运动数据到我方系统**。

**核心区别：**

| 维度 | 人员注册对接 | 运动数据推送对接 |
|------|-------------|-----------------|
| 角色 | 我方是客户端（调用方） | 我方是服务端（接收方） |
| 接口方向 | 我方 → 大沩API | 大沩设备 → 我方API |
| 认证方式 | Token + Authorization头 | check_string + timestamp签名（Header） |
| 是否需要后端 | 否（纯前端直调） | **是（必须有可访问的服务端接收推送）** |

| 5 | 获取临时域名 | 隧道启动后会分配类似 `xxxx.trycloudflare.com` 的临时域名 |

**启动脚本（推荐）**：

```bash

{
  "scripts": {
    "dev": "vite",
    "server": "node src/server/index.js",
    "tunnel": "cloudflared tunnel --url http://localhost:8000",
    "dev:tunnel": "concurrently \"npm run dev\" \"npm run server\" \"npm run tunnel\""
  }
```

**端口说明**：
- 前端 Vite：`5173`（开发服务器，HTTPS）
- 推送接收服务：`8000`（Node.js + Express）
- Cloudflare Tunnel 映射到 `8000`
- 现有 `/api` 代理指向 `8080`（主后端服务）

**临时域名格式**：`https://xxxx.trycloudflare.com`（每次启动可能不同）

**优势**：
- ✅ 无需公网IP，穿透内网
- ✅ 自动HTTPS，安全加密
- ✅ 配置简单，一键启动
- ✅ 支持WebSocket（后续扩展）

**替代方案**：

| 方案 | 优点 | 缺点 |
|------|------|------|
| ngrok | 成熟稳定 | 免费版速度慢，域名随机 |
| Localtunnel | 开源免费 | 服务不稳定 |

### 4.3 签名验证算法

```javascript
// src/server/middleware/auth.js
const crypto = require('crypto')

const verifyPushSign = (req, res, next) => {
  const timestamp = req.headers['timestamp']
  const sign = req.headers['sign']
  const checkString = require('../config').checkString

  // 1. 检查必要header
  if (!timestamp || !sign) {
    return res.status(200).json({ code: -1, message: '缺少签名参数' })
  }

  // 2. 检查时间戳有效性（允许5分钟偏差）
  const now = Date.now()
  const diff = Math.abs(now - Number(timestamp))
  if (diff > 5 * 60 * 1000) {
    return res.status(200).json({ code: -1, message: '时间戳过期' })
  }

  // 3. 验证签名: MD5(check_string + timestamp)
  const expectedSign = crypto
    .createHash('md5')
    .update(checkString + timestamp)
    .digest('hex')
    .toLowerCase()

  if (sign !== expectedSign) {
    return res.status(200).json({ code: -1, message: '签名验证失败' })
  }

  next()
}

module.exports = { verifyPushSign }
```

## 九、签名验证对照表

### 9.1 推送签名 vs 调用签名

| 维度 | 调用大沩API（人员注册） | 接收大沩推送（运动数据） |
|------|----------------------|----------------------|
| 方向 | 我方 → 大沩 | 大沩 → 我方 |
| 密钥 | access_key_id + access_key_secret | check_string |
| 签名算法 | MD5(access_key_id + timestamp + access_key_secret) | MD5(check_string + timestamp) |
| 签名位置 | Body中的sign字段 | Header中的sign字段 |
| 时间戳位置 | Body中的timestamp字段 | Header中的timestamp字段 |
| Token | 需要JWT Token | 不需要Token |

### 9.2 签名验证示例

```
假设 check_string = "abc123"
timestamp = 1784699567574

sign = MD5("abc123" + "1784699567574")
     = MD5("abc1231784699567574")
     = "32位小写hex字符串"
```

```javascript
const crypto = require('crypto')
const config = require('../config')

module.exports = (req, res, next) => {
  const sign = req.headers.sign
  const timestamp = req.headers.timestamp
  
  if (!sign || !timestamp) {
    return res.status(401).json({ code: 401, message: '缺少签名参数' })
  }
  
  // 验证时间戳（5分钟有效期）
  const now = Date.now()
  if (Math.abs(now - parseInt(timestamp)) > 5 * 60 * 1000) {
    return res.status(401).json({ code: 401, message: '时间戳过期' })
  }
  
  // 验证签名
  const expectedSign = crypto
    .createHash('md5')
    .update(config.checkString + timestamp)
    .digest('hex')
  
  if (sign !== expectedSign) {
    return res.status(401).json({ code: 401, message: '签名验证失败' })
  }
  
  next()
}
```

```javascript
import axios from 'axios'
import { SPORT_TYPES } from '@/config/sport-types'

const pushApi = axios.create({
  baseURL: import.meta.env.VITE_PUSH_SERVER_URL + '/api/sports',
  timeout: 10000

export const getSportResults = async (params) => {

export const getSportRanking = async (sportType, params) => {
  const response = await pushApi.get(`/ranking/${sportType}`, { params })
  return response.data
}

export const getSportStatistics = async (params) => {
  const response = await pushApi.get('/statistics', { params })
  return response.data

export const getRecentPush = async (params) => {
  const response = await pushApi.get('/recent', { params })
  return response.data
}

export const transformPushData = (data) => {
  const sportInfo = SPORT_TYPES[data.sport_type] || { name: '未知', unit: '' }
  return {
    id: data.id,
    sportName: sportInfo.name,
    sportUnit: sportInfo.unit,

    score: data.score,
    startTime: new Date(data.start_time).toLocaleString(),
    duration: data.all_time + '秒',
    videoUrl: data.video_url,
    faceUrl: data.face_url
  }
}
```

## 十一、风险与注意事项

### 11.1 关键风险

| 风险 | 等级 | 说明 | 应对措施 |
|------|------|------|----------|
| check_string未提供 | **高** | 大沩尚未分配推送校验密钥 | 联系大沩确认，开发阶段可临时设为空或固定值 |
| 无后端部署环境 | **高** | 当前纯前端，推送需要可访问的服务端 | 生产需部署Node服务 |
| 大沩设备端推送频率 | 中 | 高频推送可能导致服务端压力 | 实现请求限流、异步存储 |
| person_id为空 | 中 | 未识别人员时person_id为空字符串 | 前端展示时处理为空，支持按时间/设备筛选 |
| 视频文件体积大 | 中 | mp4文件可能较大，占用存储空间 | 配置文件大小限制、定期清理策略 |
| 运动类型扩展 | 低 | 文档说明后续会增加更多运动项目 | 枚举设计为可扩展，新类型不影响旧逻辑 |

### 11.2 待确认事项

| 事项 | 说明 | 状态 |
|------|------|------|

| 推送URL | 大沩后台配置的接收地址格式 | ⏳ 待确认 |
| 推送频率 | 设备推送数据的频率和并发量 | ⏳ 待确认 |
| 视频推送 | 是否开启视频推送，视频格式和大小 | ⏳ 待确认 |
| 人脸抓拍 | 是否开启人脸抓拍推送 | ⏳ 待确认 |
| 数据有效期 | 推送数据是否需要长期存储 | ⏳ 待确认 |
| 学校隔离 | 不同学校的推送数据是否用不同check_string | ⏳ 待确认 |

### 11.3 部署注意事项

1. **生产环境**需要部署Node.js服务端，不能仅靠前端静态文件
2. 接收推送的URL需要是**公网可访问**的地址（或大沩设备能访问的内网地址）
3. 建议使用 **HTTPS** 接收推送（生产环境）
4. 文件存储建议后续迁移到 **OSS/云存储**，避免本地磁盘限制
5. 数据库建议后续从JSON文件迁移到 **SQLite/MySQL**

```bash
cloudflared tunnel create hailin-sports

cloudflared tunnel list
```

```bash
cloudflared tunnel route dns hailin-sports your-domain.com
cloudflared tunnel run hailin-sports
```

```
│ 1309名学生    │                    │ 按人关联展示  │
└──────────────┘                    └──────────────┘
```

### 15.2 数据流整合

```
┌─────────────────────────────────────────────────────────┐
│                    数据流全景                             │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ① 人员同步（已有）                                      │
│  前端 → 大沩API → 获取学生/班级/职工列表                   │
│                                                         │
│  ② 运动数据推送（新增）                                   │
│  大沩设备 → 我方服务端 → 存储 → 前端展示                   │
│                                                         │
│  ③ 数据关联                                             │

│                                                         │
└─────────────────────────────────────────────────────────┘
```
