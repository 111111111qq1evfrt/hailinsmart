# 大沩智慧体育人员注册对接 - 前端实现计划

## 一、文档概述

本文档基于《大沩智慧体育人员注册对接文档 4.1》，规划前端API封装实现方案。大沩智慧体育作为数据提供方，我方前端需要调用其API完成人员管理、班级管理等功能。

## 三、配置管理

### 3.1 架构说明

**纯前端直接调用大沩API**（当前无后端）：

```
前端 → 大沩API（直接调用）
```

**安全说明：**
- 当前无后端，`access_key_secret` 必须在前端处理
- 通过环境变量注入，不在代码中硬编码
- **后续有后端后，可迁移为后端代理模式**，将签名逻辑移至后端

### 3.2 环境配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `DAIWEI_API_BASE_URL` | 大沩API基础地址 | `''` |
| `DAIWEI_ACCESS_KEY_ID` | 第三方调用ID | `''` |
| `DAIWEI_ACCESS_KEY_SECRET` | 第三方调用秘钥 | `''` |
| `DAIWEI_SCHOOL_ID` | 学校ID | `''` |
| `DAIWEI_ENABLED` | 是否启用大沩API | `false` |

### 3.3 配置文件

```javascript
// src/config/daiwei.js
export const daiweiConfig = {
  baseUrl: process.env.VUE_APP_DAIWEI_API_BASE_URL || '',
  accessKeyId: process.env.VUE_APP_DAIWEI_ACCESS_KEY_ID || '',
  accessKeySecret: process.env.VUE_APP_DAIWEI_ACCESS_KEY_SECRET || '',
  schoolId: process.env.VUE_APP_DAIWEI_SCHOOL_ID || '',
  enabled: process.env.VUE_APP_DAIWEI_ENABLED === 'true'
}
```

### 3.4 安全注意事项

- `access_key_secret` 通过环境变量注入（`VUE_APP_DAIWEI_ACCESS_KEY_SECRET`），不在代码中硬编码
- 签名生成在前端完成（`MD5(access_key_id + timestamp + access_key_secret)`）
- Token存储在 `sessionStorage`，页面关闭后自动清除
- **后续有后端后，建议迁移为后端代理模式**：签名逻辑移至后端，前端不接触 `access_key_secret`

## 四、API封装详细设计

### 4.1 核心模块 - daiweiApi.js

#### 4.1.1 Token管理

| 方法名 | 接口路径 | HTTP方法 | 描述 |
|--------|----------|----------|------|
| `getToken()` | `/v3/token/get_token` | POST | 获取认证Token |
| `refreshToken()` | `/v3/token/get_token` | POST | 刷新Token |

**实现要点：**
- Token过期自动刷新（请求拦截器检查 + 响应拦截器重试）
- Token存储：`sessionStorage` + 内存缓存
- 签名生成：前端完成（`MD5(access_key_id + timestamp + access_key_secret)`）

**Token自动刷新流程：**

```
┌─────────────────────────────────────────────────────────────┐
│                    请求拦截器                               │
├─────────────────────────────────────────────────────────────┤
│  1. 检查Token是否存在                                       │
│  2. 检查Token过期时间（提前30秒刷新）                        │
│  3. 未过期 → 直接发送请求                                   │
│  4. 已过期 → 同步刷新Token → 再发送请求                      │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                    响应拦截器                               │
├─────────────────────────────────────────────────────────────┤
│  1. 检查响应code                                            │
│  2. String(res.code) === '9000'（认证失败） → 刷新Token → 重试请求一次 │
│  3. 重试仍失败 → 清除Token → 跳转登录                        │
│  4. 其他错误 → 提示用户                                     │
└─────────────────────────────────────────────────────────────┘
```

#### 4.1.5 分页参数转换

**大沩API使用 `offset/count` 分页，前端使用 `page/size` 分页，封装层需做转换：**

```javascript
// 请求参数转换：page/size → offset/count
const transformPageParams = (params) => {
  if (params.page !== undefined && params.size !== undefined) {
    return {
      ...params,
      offset: (Number(params.page) - 1) * Number(params.size),
      count: params.size
    }
  }
  return params
}

// 响应参数转换：offset/count → page/size
const transformPageResponse = (response, page, size) => {
  if (response.data && response.total_count !== undefined) {
    return {
      ...response,
      data: {
        list: response.data,
        total: response.total_count,
        page: page || 1,
        size: size || 10
      }
    }
  }
  return response
}
```

## 五、加载蒙版组件设计

### 5.1 设计目的

为提升用户体验，所有调用大沩接口的页面在数据加载期间需显示加载蒙版，避免用户看到临时的Mock数据或空白页面。

### 5.2 组件规范

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `visible` | Boolean | false | 是否显示蒙版 |
| `text` | String | '加载中...' | 主文案 |
| `subText` | String | '' | 辅助文案 |

### 5.3 使用规范

**所有对接大沩API的页面必须遵循以下流程：**

```
页面渲染 → 显示加载蒙版(loading=true) → 调用接口 → 接口返回 → 隐藏蒙版(loading=false) → 显示真实数据
```

**关键规则：**
1. 页面初始化时 `loading = true`，显示蒙版
2. 接口调用成功后 `loading = false`，隐藏蒙版并显示真实数据
3. 接口调用失败后 `loading = false`，隐藏蒙版并显示Mock数据（降级）
4. 蒙版组件统一使用 `src/components/LoadingOverlay.vue`

## 六、签名生成算法

### 6.1 Token接口签名

```javascript
// 签名公式：MD5(access_key_id + timestamp + access_key_secret)
const generateTokenSign = (accessKeyId, accessKeySecret, timestamp) => {
  const raw = accessKeyId + timestamp + accessKeySecret
  return md5(raw).toLowerCase()
}
```

### 6.2 其他接口签名

所有需要Authorization的接口，请求头必须携带：
- `Authorization`: `Bearer ${token}`

## 十、注意事项

1. **学校隔离**：每个学校需要独立配置 `school_id` 和 `access_key`
2. **Token过期**：请求拦截器提前30秒检查，响应拦截器捕获9000错误码后自动重试
3. **签名安全**：`access_key_secret` 通过环境变量配置，不硬编码在代码中
4. **网络环境**：大沩API可能部署在内网，需确认网络可达性
5. **数据同步**：前端修改数据后需要同步到本地存储和大沩API
6. **图片格式**：人脸图片仅支持jpg格式
7. **分页转换**：封装层自动处理 `page/size` 与 `offset/count` 的转换
8. **Mock模式**：通过配置开关在真实API和模拟数据间切换

### 13.1 新增学生对接方案

**前端数据结构 → 大沩API参数映射：**

| 前端字段 | 大沩API字段 | 类型 | 必填 | 说明 |
|----------|-------------|------|------|------|

| `gender` | `gender` | number | ✅ | 0未知/1男/2女 |
| `className` | `class_id` | string | ✅ | 需要转换为班级ID |
| `grade` | - | - | - | 由班级ID决定 |
| `birthday` | - | - | - | 大沩API不支持 |

**对接步骤：**

1. 在 `StudentManagement.vue` 的 `handleAdd` 方法中，调用 `addStudent()` API

### 13.5 数据同步策略

**双向同步流程：**

```
前端操作 → 本地存储更新 → 大沩API调用 → 列表刷新
     ↓                     ↓
  成功/失败              成功/失败
     ↓                     ↓
  更新UI状态              更新UI状态
```

**本地存储Key**：`students_{schoolId}`

**同步规则：**

| 操作 | 本地存储 | 大沩API | 降级策略 |
|------|----------|---------|----------|
| 新增学生 | 立即写入 | 异步调用 | API失败时保留本地数据 |
| 修改学生 | 立即更新 | 异步调用 | API失败时保留本地数据 |
| 删除学生 | 立即删除 | 异步调用 | API失败时恢复本地数据 |
| 人脸上传 | 更新人脸URL | 异步调用 | API失败时显示警告 |
